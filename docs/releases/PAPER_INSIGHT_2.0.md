# Paper Insight 2.0 Release Notes

发布日期：2026-08-31
版本：`2.0.0`

## 版本定位

Paper Insight 2.0 引入新的周报执行框架。最终目标是提高发布稿的可信度和阅读价值：入选、评分、排序和写作均以论文原文证据为基础，发布前必须经过完整质量检查。

新框架以 Agent Loop 组织原文获取、证据提取、独立复评、横向校准、确定性选稿、分段写作和发布前 QA，并通过 Agent Harness 管理结构化输入输出、异步任务、有限并发、定向修正、管理员决策和完整 Trace。它不是一次模型调用直接生成整份周报，也不是多个 Agent 自由对话，而是服务端控制的分阶段执行流程。

## 六项关键技术特性

### 1. 原文证据链

摘要只用于发现推荐候选，不能进入周报发布证据链。进入周报的论文必须成功获取 arXiv HTML 原文并通过原文质量门。关键事实、数字、方法、实验结果和限制条件必须关联到对应论文的证据摘录。

### 2. 单篇隔离执行

Evidence、Review、逐篇 Writer 和逐篇语义 QA 均按一篇论文一次调用执行。不同论文通过有限任务池并发处理，但不会在一次请求中混入多篇完整原文，从而降低跨论文串写、数字错配和结论归属错误。

### 3. 横向校准闭环

每篇论文先独立完成四维评价，服务端按固定公式计算分数。Calibration Agent 只识别疑似误判的论文和维度，不直接修改总分；被质疑的维度会进入定向 Review，随后由服务端重新计算并再次确认相对顺序。

### 4. 分段可信写作

周报不再由一次调用整篇生成。每篇论文的正文独立写作，导读、整体观察和结尾根据最终入选论文综合生成，最后由服务端按照确定顺序和固定结构组装。

### 5. 局部修正机制

每个可修复的质量门默认允许三次定向修正。修正只作用于问题指定的论文、artifact 或字段，已经通过检查的内容保持不变。自动修正耗尽后，任务暂停并由管理员决定继续修正、跳过论文或退出任务。

### 6. 全程可追溯

运维 Trace 记录各阶段的输入、模型响应、结构化产物、耗时、重试、修正和最终决策。Trace 仅供管理员运维和问题定位，不进入面向读者的发布稿，并在落盘前删除认证信息等敏感字段。

## 周报发布能力

- 周报候选范围扩展到当前推荐列表中的全部可见推荐论文，不按论文发表时间排除。
- 主候选不足时自动从原推荐列表增补；候选耗尽后按实际达标数量发布，只有零篇合格论文时才无法形成周报。
- 最终选稿只使用原文复评、横向校准结果和确定性服务端规则，不使用旧推荐分数影响周报评分或正文。
- 一篇论文处理失败不会取消其他论文；可以继续处理下一篇，并在可用时从增补池补充候选。
- 单篇稿件修正只重试失败论文，保留已经通过的逐篇稿件。
- 发布前执行确定性 QA、逐篇语义 QA 和整稿语义 QA；任何最终发布稿都必须通过强制质量门。
- 周报作为后台异步 Job 执行，浏览器关闭后任务继续运行；重新打开页面可以恢复当前任务状态和 Trace。
- 全局只允许一个周报任务运行，避免重复创建和资源争用。
- 管理员界面区分未开始、运行中、等待处理、发布和退出状态，并提供阶段、耗时、产物与可读告警。

## 推荐列表与模型调用改进

- 推荐分析固定使用三路有限并发，每个请求只分析一篇论文。
- 单篇分析失败不再取消其他论文；支持只重试失败论文或跳过后继续。
- 查询构建器默认选择全部网络相关背景领域词，仍允许用户手动取消。
- 候选不足时保持关键词不变，依次扩展到最近 14 天和 30 天，并显示实际使用范围。
- 推荐列表候选目标和分析上限提高到 100，自动补轮最多 10 轮。
- GLM 默认模型更新为 `glm-5.3`，继续使用既有 Anthropic 兼容接口和请求结构。
- 推荐分析最大输出预算提高到 `128000` token；超长或不完整结构化响应会明确失败并提供重试，不截断后继续使用。

## 数据与兼容性

- 运行环境继续要求 Node.js 20 或更高版本。
- 现有环境变量和本地 arXiv 缓存可继续使用，不需要数据库迁移。
- 推荐列表和已发布周报仍保存在浏览器 `localStorage`；更换浏览器、设备或清理站点数据不会自动恢复这些列表。
- 周报任务状态、Trace、阶段产物和原文缓存保存在服务端本地目录。
- Trace 默认最多保留最近 20 次任务且不超过 30 天。

## 当前限制

- 原文发布链路当前只支持 arXiv HTML，不使用摘要、PDF 或 TeX 作为发布兜底。
- 服务重启后不做周报任务断点恢复，遗留运行任务会标记为中断。
- 单次横向校准最多处理 30 篇论文；跨批锚点和分层校准尚未实现。
- 第一阶段只显示当前任务和单次完整 Trace，不提供跨任务统计看板。
- 推荐列表和发布周报元数据尚未迁移到服务端持久化。
