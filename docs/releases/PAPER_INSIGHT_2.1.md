# Paper Insight 2.1 Release Notes

发布日期：2026-09-20
版本：`2.1.0`

## 版本定位

Paper Insight 2.1 是周报 Agent Loop 的稳定性与可用性版本。2.0 建立了基于原文证据、分阶段执行和发布前 QA 的基本框架；2.1 根据多轮真实论文灰度结果，重点解决结构化响应不稳定、语义门禁过严、单篇失败导致整批重跑、人工复核信息不足以及任务状态不清晰等问题。

最终标准保持不变：显著提升发布稿的可信度和阅读价值。Agent Loop 与 Trace 只服务于管理员运维、复核和问题定位，不进入面向读者的周报正文。

## Agent Harness

Agent Harness 是服务端执行与治理层，不是单独的大模型，也不是多个 Agent 的自由对话。它负责：

- 按八个阶段推进候选与全文门、Evidence、Review、Calibration、Selection、写作、QA 和发布结果。
- 为每个 Agent 构造最小必要上下文，单次逐篇调用只包含一篇论文的原文与绑定产物。
- 通过 JSON/Schema 契约检查论文身份、必填字段、sourceId、evidenceRefs、产物集合和发布结构。
- 将具体错误路径、失败原因和修正要求反馈给原阶段，执行字段级或单篇范围的局部修正。
- 保存已经通过的阶段 artifact；后续失败只重试对应论文或阶段，不默认重新执行整份任务。
- 持久化后台任务状态、管理员决定和脱敏 Trace，并保证 publish 才覆盖上一份有效周报。

## 主要更新

### 1. Evidence 响应恢复

- 将响应格式恢复与证据内容校验分离。JSON 截断、包装层、缺失闭合符和 Schema 形状问题先进入有限次数的结构恢复，不再错误解释为论文质量不足。
- 格式修正会携带解析位置、缺失字段和预期结构，但不会把上一次未经验证的完整原始响应重新塞回提示词。
- 新增 source registry，为原文章节和摘录分配稳定 sourceId；Evidence 必须使用服务端提供的来源标识，不能自行生成引用。

### 2. 单篇隔离与有限并发

- Evidence、Review、逐篇 Writer 和逐篇 QA 均以单篇论文为调用边界。
- 不同论文通过有限任务池并发处理；一篇论文失败不会取消其他论文，也不会重做已经成功的论文。
- 单篇重试会保留失败阶段所需的上下游 artifact，避免退化成整份周报重新执行。

### 3. 可信度门禁分级

- 新增集中可信度策略，明确区分确定性硬门禁与语义告警。
- paperId/sourceId/evidenceRefs 归属、跨论文引用、必填产物、论文集合、评分/层级、敏感信息和发布结构仍是硬门禁。
- 数字字面差异、单位换算、事实支持充分性、范围限定、机构语义、文风和内部流程术语改为 Trace 告警或人工判断，不再单独导致论文被排除。
- 未知规则码默认降级为告警，防止新增启发式校验未经策略登记就阻断发布。

### 4. 复评、校准与确定性选稿

- Review 即使发现非阻断 Evidence 问题，也必须返回完整四维评分；服务端按照固定公式计算总分。
- Calibration 只定位疑似误判的论文和维度，不能直接修改分数；定向 Review 完成后由服务端重新计算。
- Selection 只使用原文复评和横向校准结果。默认最低达标目标为 3 篇，默认发布上限为 5 篇，上限可在 3–20 篇之间调整。
- 候选耗尽时按实际达标数量发布；只有零篇可发布论文时才无法形成周报，不使用低分论文自动补足。

### 5. 统一人工复核

- 系统处理失败、确定性证据争议和低于入选阈值的人工纳入进入统一待处理队列。
- 管理员可以看到问题字段、当前稿件片段、校验要求、实际差异和可取得的局部原文证据，不再只显示英文错误或内部规则码。
- 复核按单个问题推进。支持继续局部修正、重试当前论文或阶段、确认当前证据、保留符合条件的表述、从本期周报移除论文以及退出任务。
- 每次决定都写入回执与 Trace；关闭对话框或浏览器不会丢失当前待处理项。

### 6. 后台任务与运维界面

- 全局只运行一个周报任务。关闭浏览器后服务端继续执行，重新打开页面会回挂当前任务。
- 任务界面区分执行步骤、阶段产物和管理员待处理项，显示当前阶段、论文、完成数量、排除数量和可读耗时。
- Trace 按八个阶段组织摘要，同时保留原始调用和 artifact 供排查；认证字段在落盘前统一脱敏。
- 本地 watchdog 使服务在关闭 Codex 或浏览器后继续运行，并在子进程异常退出后自动重启。服务进程重启仍不做任务断点恢复。

### 7. 模型调用与错误说明

- 默认模型为 `glm-5.3`，使用 BigModel Coding OpenAI 兼容端点 `https://open.bigmodel.cn/api/coding/paas/v4/chat/completions`，默认 `reasoning_effort=low`。
- 周报长响应使用流式读取，结构化输出预算与响应字符上限分别控制，不再把截断响应当作完整 JSON。
- 网络不可达、认证失败、余额不足、速率限制、响应超时和结构错误分别给出可执行的中文提示。

## 数据与兼容性

- 推荐列表和已发布周报仍保存在浏览器 `localStorage`；任务状态、Trace、阶段 artifact 和原文缓存保存在本地服务目录。
- 浏览器关闭后任务继续；服务进程重启后，运行中的任务标记为中断，不做断点续跑。
- 原文发布链路仍只接受通过质量门的 arXiv HTML，不使用摘要、PDF 或 TeX 作为发布兜底。
- Trace 默认最多保留最近 20 次任务且不超过 30 天。
