# 周报单篇人工复核与保底入选设计

## 背景

最近一次真实周报任务从 24 篇通过全文门的候选中只发布 2 篇。主要损失并非论文质量不足，而是 Evidence 响应结构异常、确定性校验误判、自动修正失败和 Calibration 未收敛被统一处理为“排除论文”。这会把 PaperInsight 自身的处理失败错误地解释为论文不值得阅读。

本设计将单篇失败按性质拆分，并把现有的证据人工复核扩展为统一的待复核队列。最终目标仍是提升发布稿的可信度和阅读价值；人工复核只处理自动化无法可靠判定的局部问题，不能绕过事实与证据底线。

## 目标

- 推荐列表中的论文通过全文质量门后，不因模型格式错误、系统处理失败、校验器误判或自动修正耗尽而被静默排除。
- 明确区分“论文质量不足”和“PaperInsight 处理失败”。处理失败不降低论文分数，也不形成论文质量结论。
- 在同一个管理员对话框中展示待复核队列、具体问题、局部原文证据、操作效果和不可覆盖门禁。
- 允许管理员人工纳入低于默认入选线的论文，同时保留真实分数、入选原因和完整 Trace。
- 其他论文继续并行处理；单篇待复核不立即阻塞整个任务。
- 所有人工决定和自动恢复都可追溯、可恢复页面状态，并只影响明确的论文和问题。

## 非目标

- 不允许管理员强制发布没有有效全文、论文身份不一致、证据与原文冲突、跨论文串写或泄漏敏感配置的内容。
- 不把内部评分、人工覆盖或 Agent Loop 过程写进读者可见的周报正文。
- 不增加新的发布终态。最终仍只有 `publish` 和 `reject`；`manual_review` 是运行中的暂停状态。
- 不实现多任务队列、服务重启后的断点恢复、跨任务统计或多人权限控制。
- 不提供任意编辑整份周报的通用编辑器；修改仍通过局部修正或明确的证据确认完成。

## 失败分类

每个单篇失败必须先归入以下一种类型，不能直接使用笼统的“未通过质量门”。

### 1. 系统处理失败 `processing_failure`

包括网络或模型调用最终失败、完整响应的 JSON/Schema 形状不兼容、响应截断、服务端规范化失败，以及缺少阶段产物等情况。

处理规则：

- 不改变论文分数，不记录为论文内容不合格，不进入自动排除计数。
- 优先执行确定性恢复；无法恢复时允许只重试当前论文的失败阶段。
- 重试期间其他论文继续处理。
- 自动恢复和重试耗尽后进入待复核队列。单篇故障允许“重试本论文”“跳过论文”或“退出任务”；Calibration、报告级 QA 等跨论文阶段故障允许“重试当前阶段”或“退出任务”，不能把一次批次故障映射为所有论文质量不合格。
- 只有完整产物通过对应 Schema 和可信度门禁后，论文才可以继续进入后续阶段。

### 2. 证据争议 `evidence_dispute`

包括稿件表述与绑定原文摘录之间存在可解释差异、数字或单位等价关系无法确定、校验器可能误判，以及自动局部修正仍未解决的事实或证据边界问题。

处理规则：

- 必须展示稿件待核对片段和 `evidenceRefs` 对应的局部原文，不能只显示规则码。
- 允许“定向修正本条表述”“确认证据充分”和“跳过论文”。
- “确认证据充分”只放行界面实际展示的稳定问题键，并返回产生问题的 QA 阶段重新检查。
- 没有可展示原文证据、证据明确冲突、论文身份不一致或跨论文串写时，不提供确认按钮。
- 证据确认不改变论文分数，不等于整篇论文或整份周报通过。

### 3. 质量与分数不足 `quality_below_threshold`

论文已经通过全文、身份和证据门，但 Review 或 Calibration 的真实分数低于默认入选线，或横向校准无法形成稳定的入选结论。

处理规则：

- 显示四维分、最终分、低分原因、同批次校准位置和默认入选线。
- 当已达标论文不足 `minSelectedCount` 时，优先把接近阈值且证据门已通过的论文加入待复核队列；不自动把低分论文写入周报。
- 管理员可以填写中文理由后选择“人工纳入本期周报”，也可以保持不入选。
- 人工纳入只覆盖 Selection 的分数阈值，不修改真实分数，也不绕过全文、身份、证据、跨论文归因、敏感信息和最终整稿 QA。
- Trace 保存真实分数、默认决策、人工理由、管理员动作、时间和重新执行的后续阶段。

## 自动排除边界

自动排除只适用于可以由服务端明确证明的候选资格问题：

- 用户已经隐藏或候选重复。
- 无法获得有效全文，或全文未达到原文质量门。
- 论文身份与原文确定性不一致，且无法安全恢复。
- 原文自身确实不包含生成目标所需的任何可用证据，并且系统无法通过收缩表述形成可信稿件。

模型返回格式、网络失败、生成稿校验失败、修正失败和校准未收敛均不属于上述资格问题。它们应进入恢复或人工复核，不得静默排除。

## 任务流程

单篇处理采用“继续处理、集中决策”的方式：

~~~text
候选论文并发处理
→ 成功论文继续后续阶段
→ 单篇异常写入 manualReview.items
→ 其他论文和 reserveCandidates 继续
→ 到 Selection 前形成统一待复核队列
→ 管理员逐项处理
→ 受影响范围重新校验或重新校准
→ 进入写作与最终 QA
→ publish / reject
~~~

如果问题发生在写作或 QA 阶段，则暂停在当前阶段显示同一队列；管理员处理一个问题后，只重跑该论文及受影响的下游阶段。论文集合发生变化时，必须重新执行 Calibration、Selection、Editorial Plan 和后续写作，不能复用旧的跨论文产物。

## 管理员界面

采用一个统一的人工复核对话框，包含四个区域：

1. 顶部任务健康状态：当前阶段、已处理数量、待复核数量、最近事件和阶段耗时。明确区分“仍在运行”“等待管理员”和“连接中断”。
2. 左侧待复核队列：每篇论文显示论文 ID、标题、问题类型和处理状态。系统处理失败、证据争议和质量不足使用不同文字标签，不能只靠颜色区分。
3. 中间问题详情：用中文展示已经完成的步骤、未达到的要求、实际差异、局部证据、自动修正记录以及推荐操作。
4. 右侧可信度检查：显示全文、身份、证据、跨论文隔离和敏感信息状态，并明确列出当前操作不能覆盖的门禁。

底部操作区根据问题类型变化：

- 系统处理失败：确定性恢复并继续；单篇范围可重试本论文、跳过论文或退出任务，跨论文范围可重试当前阶段或退出任务。
- 证据争议：定向修正当前表述、确认证据充分、跳过论文、退出任务。
- 质量与分数不足：人工纳入、保持不入选、退出任务。

跳过论文和退出任务需要二次确认。人工纳入必须先填写理由；理由不足时按钮禁用并显示可读提示。

## 状态与数据契约

Job 的 `manualReview` 使用统一队列，而不是只保存一个笼统问题：

~~~json
{
  "status": "waiting_admin",
  "resumeStage": "selection",
  "items": [
    {
      "itemId": "stable-id",
      "paperId": "2608.28194",
      "kind": "evidence_dispute",
      "sourceStage": "paper_semantic_qa",
      "issueKeys": ["stable-problem-key"],
      "summary": "中文问题摘要",
      "details": [],
      "evidencePackage": {},
      "scoreSnapshot": null,
      "gateStatus": {},
      "allowedActions": ["continue_repair", "confirm_evidence", "skip_paper"]
    }
  ]
}
~~~

约束：

- `itemId` 和 `issueKeys` 在同一次任务内稳定，页面刷新后保持一致。
- `allowedActions` 由服务端根据问题类型和门禁状态生成，前端不得自行推导权限。
- `evidencePackage` 沿用现有有界裁剪规则，Job 和 Trace 保存同一份快照。
- `scoreSnapshot` 保存四维分、最终分、阈值、Calibration 结论和默认 Selection 决策。
- 每个管理员动作使用幂等的 decision ID，重复点击不得重复修改任务。
- 任务等待管理员时仍属于 `running`；当前全局单任务限制继续生效。

## 操作后的重新执行范围

- `retry_paper`：从该论文失败的最小阶段重跑，成功后继续原流水线。
- `retry_stage`：只重跑失败的 Calibration 或报告级阶段，保留已经通过的单篇产物；批次失败不得清空或排除整批论文。
- `continue_repair`：只修改问题映射出的路径，完整复检该 artifact，并继续对应 QA。
- `confirm_evidence`：只登记当前问题键的证据确认，从产生问题的 QA 阶段重新检查。
- `include_below_threshold`：将论文标记为 `selectionSource=admin_override`，保留真实分数，重新执行 Selection 之后的全部阶段。
- `keep_excluded` 或 `skip_paper`：记录管理员原因，移出候选集合；如论文集合发生变化，重新校准其余候选并尝试 reserveCandidates。
- `exit_task`：写入最终 `reject`，保留旧周报、当前 artifacts 和完整 Trace。

## Trace 与可读性

每个待复核项和管理员动作至少记录：

- 问题类型、来源阶段、论文 ID、稳定问题键。
- 自动尝试次数、每次目标路径、前后差异和最终失败详情。
- 界面展示的中文摘要和局部证据快照。
- 操作前后的可信度门状态和 Selection 决策。
- 管理员动作、填写理由、操作时间、decision ID 和恢复阶段。

管理员界面不直接展示英文校验描述或内部规则码。规则码保留在 Trace 的技术详情中，用于排查和回归用例关联。

## 测试策略

实现必须测试先行，并把已发现的真实失败加入固定回归样本。

### 分类与流程

- Evidence 返回完整但外层结构不同，归类为 `processing_failure`，不排除论文。
- 网络、429、503、截断和 Schema 恢复失败均不改变论文分数。
- 一篇进入待复核队列时，其他论文继续处理。
- 多篇问题在 Selection 前合并为稳定队列，刷新页面后不丢失。
- 管理员只重试当前论文，不重复运行已成功论文的独立阶段。
- 论文集合变化后重新执行 Calibration 和全部跨论文产物。

### 证据复核

- 同时展示稿件片段、原文章节、锚点和局部摘录。
- 没有可展示证据、身份不一致或跨论文串写时不允许确认。
- 确认只放行展示的问题键，新问题仍保持阻断。
- 数字单位等价先由确定性规则处理，不无意义地进入人工复核。

### 人工纳入

- 低于阈值但证据门通过的论文可以在填写理由后人工纳入。
- 未填写理由时按钮禁用。
- 人工纳入不修改真实分数，并在 Trace 标记 `admin_override`。
- 证据门、身份门或跨论文隔离未通过时，即使填写理由也不能人工纳入。
- 人工纳入后仍必须通过逐篇 QA 和最终整稿 QA。

### 界面

- 三类问题使用不同中文说明和操作集合。
- 队列、详情、可信度检查和底部操作在长内容下不重叠，外层对话框可滚动。
- 窄屏布局按队列、详情、可信度检查、操作区顺序纵向排列。
- 页面恢复后显示当前任务、当前待复核项和后台执行状态。
- 所有耗时使用“分、秒”或“时、分、秒”的可读格式。

## 验收标准

- 通过全文门的论文不会因为 PaperInsight 的格式、网络、生成或修正问题被静默排除。
- 管理员能区分论文质量不足、证据争议和系统处理失败，并看到每个问题的具体原因。
- 证据复核能直接对照周报表述和局部原文，不需要阅读内部 Trace 才能理解。
- 低于默认阈值的论文只有在证据门通过且填写理由后才能人工纳入，真实分数不被篡改。
- 人工决定不能绕过全文、身份、事实证据、跨论文隔离、敏感信息和最终 QA。
- 单篇问题不阻断其他论文处理；管理员完成队列后，任务能从正确阶段继续并最终产生 `publish` 或 `reject`。
- 每个自动恢复、人工确认、人工纳入、跳过和退出动作都有完整且可读的 Trace。
